# SealDesk 产品范围与连接约定

更新：2026-10-16。本文描述当前 main 的实现边界，替代早期原型阶段的逐轮开发记录。
构建与验证入口见 [BUILDING.md](../BUILDING.md) 和 [README](../README.zh-CN.md)。

## 产品定位

即用即走的远程桌面工具。用户主动打开共享，控制端扫码或选择局域网设备连接。
不需要账号，不接入 RustDesk ID 注册、hbbs/hbbr 中继或地址簿同步。

公网与局域网是同一个产品的连接路径，不是两套完整的产品模式。
沿用上游会话、认证、权限与本地 IPC；不为传输替换重写这些机制。

## 当前连接路径

| 路径 | 引导与传输 | 授权 |
| --- | --- | --- |
| SealDesk 公网配对 | 配对码包含 tc 地址，Tailcat 使用 WireGuard；可直连时走 UDP，否则由 DERP 转发加密流量 | 沿用会话密码或点击授权 |
| SealDesk 局域网 | 私有 IPv4 发现广播，签名临时密钥交换及加密传输 | 首次点击接受，可记住控制端公钥和权限 |
| RustDesk 兼容直连 | 原版发现／IP 直连协议，未加密，明确提示 | 原版密码或点击授权 |

原版 RustDesk 可控制 SealDesk，SealDesk 也可控制开启直接 IP 访问的原版 RustDesk。
兼容不包括原版 ID 服务器或中继连接。

两种直连协议共用 TCP 21118；仅在共享本机开启，且「直接 IP」开关打开时监听。
监听地址只包括本机私网 IPv4（10/8、172.16/12、192.168/16）和 IPv6 ULA，不退回 0.0.0.0 或 ::。
网卡枚举失败时沿用 Android 已上报的私网地址，仍然不绑全地址。
明文 RustDesk 兼容默认关闭，需把 `sealdesk-rustdesk-compat` 设为 Y，打开时界面给出警告。
UDP 21119 的发现范围维持私有 IPv4 网卡，不纳入公网、IPv6 或 100.64.0.0/10 接口。`enable-lan-discovery` 关闭后不再应答发现。
不支持广播或隔离客户端的网络可能无法自动发现。

## 生命周期与会话

- Linux 普通启动进入控制模式，需要点击“共享本机”才接受连接。
- `sealdesk --host` 显式打开共享；不安装 systemd 守护服务或开机自启。
- 关闭共享会拒绝新连接并结束被控会话；关闭主窗口会关闭会话窗口并退出应用。
- 主动关闭控制会话后，不继续重拨；意外网络中断沿用重连流程。
- 网络恢复期间保留与对端绑定的恢复认证，不能因此绕过密码或降低传输加密。
- 允许的并发与控制权限沿用现有会话逻辑，没有另加“后来者只能观察”的角色模式。
- 撤销已记住的控制端授权会清除相应恢复凭据、断开会话，并要求下次重新接受。

当前 tc 服务端密钥保存在本机应用配置中；停止或退出不等于自动换身份。
“每次启动必换身份”“主动断开必换地址”不能作为当前实现承诺。
需要撤销地址时，使用被控页“重置地址”或 `sealdesk --tc-reset-address`。

## 配对码

```text
SEALDESK:V:1;A:<tc-address>;P:<temporary-password>;N:<device-name>;E:<unix-seconds>;;
```

| 字段 | 含义 |
| --- | --- |
| V | 当前协议版本 1 |
| A | 必填 tc 地址，包含访问所需的密钥信息，应视为凭据 |
| P | 可选密码；省略时沿用对端会话授权方式 |
| N | 可选设备显示名称，不作为认证身份 |
| E | 可选 Unix 秒级导入截止时间，仅由控制端检查 |

前缀大小写不敏感，字段名大小写敏感；支持字段转义、未知字段和 Unicode。
解析器拒绝未知版本、重复已知字段、非法时间戳、无效地址格式和过期配对码。
当前界面／CLI 默认导入有效期为 600 秒；这不代表服务端定时撤销密码或地址。

二维码显示使用黑白、M 级纠错和静区。控制端可导入图片或文本；
Android 另有摄像头扫码入口。图片读取受编码大小、尺寸和像素数量限制。
二维码到期不是撤权机制，旧码仍可能包含有效的地址和密码；
需要撤权时必须刷新密码、重置地址或撤销已记住的控制端。

## 安全边界

- SealDesk 自有局域网连接必须验证签名、对端身份和密钥确认，失败不降级。
- RustDesk 兼容直连未加密，须按界面提示决定是否继续。
- 首次点击授权、记住密钥和撤销授权不要求额外启用 2FA。
- Tailcat 到 Rust 的本机转发入口使用随机通道凭据；不是可绕过认证的公开端口。
- 配对码、tc 地址、密码、密钥及签名配置不能进入公开 issue 或测试产物。
- DERP 可以持续承载加密流量；不能承诺首次连上后一定切为 P2P，也不承诺特定 NAT 下的直连成功率。
