# SealDesk PRD：RustDesk + tailcat，扫码即连的零配置远程桌面

- 状态：草案 v0.1（2026-10-15）
- 仓库：[runseal-labs/sealdesk](https://github.com/runseal-labs/sealdesk)，默认分支 `main`
- 文档中的命令均从仓库根目录执行；工具链路径由各自环境配置。

## 1. 背景与目标

原版 RustDesk 依赖两类服务器：ID/rendezvous 服务器（hbbs，负责登记和打洞协调）和中继服务器（hbbr，打洞失败时转发流量）。
用公共服务器，就要受它的限速和可用性影响；自建，又要多维护两个服务。

[tailcat](https://github.com/tailscale/tailcat) 把 Tailscale 的数据面（WireGuard、STUN/UDP 打洞、DERP）做成了一个不需要账号和控制平面的库。
双方凭一个 `tc...` 地址在 DERP 上会合，打洞成功后就切到 P2P 直连。

**目标**：做一个单程序 SealDesk。被控端启动后直接显示二维码，控制端扫码（或载入二维码图片）就能连上。全程不需要账号、ID 服务器或中继服务器，用户无需任何配置。

**非目标**
- 不和原版 RustDesk 互通。
- 不做设备列表、账号、地址簿同步。
- 不做多 DERP 区域冗余（v1 只用 tailcat 默认中继，以后可以换成自建 derper）。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 被控端 / 控制端 | 被远程控制的机器 / 发起控制的机器 |
| tc 地址 | tailcat 服务端地址，`tc` + base64url，约 150 字符。里面含 WireGuard 公钥、预共享密钥（PSK）和 DERP 区域，**本身就是凭证** |
| DERP | Tailscale 的会合与兜底中继。这里只用来"对暗号"，打洞成功后不再经过它 |
| 配对码 | 本文定义的二维码载荷，包含 tc 地址和临时密码 |

## 3. 产品形态

一个可执行文件，启动时选择两种模式之一（也可以用命令行参数直接指定）：

```
sealdesk            # 首次启动弹出模式选择；之后记住上次的选择
sealdesk --host     # 被控模式
sealdesk --control  # 控制模式
sealdesk --control <配对码文本 | 二维码图片路径>   # 直接连
sealdesk --tc-reset-address  # 断开被控会话并撤销旧地址，再按原运行状态恢复服务
```

### 3.1 被控模式

1. 启动后在后台起 tailcat 服务，连上 DERP（目标 < 3 秒）。
2. 主界面居中显示**配对二维码**，下面附：
   - 一个"复制配对码"按钮；
   - 当前连接状态："等待连接 / 已连接：<控制端名称> / 直连 · DERP"；
   - 一个"刷新密码"按钮。
3. 收到连接后，沿用 RustDesk 现有的连接管理窗口（cm），可以断开连接、调整权限。
4. 临时密码按 RustDesk 现有规则刷新（例如会话结束后），刷新后二维码同步更新。旧临时密码不能用于新的密码登录；tc 地址保持不变。已建立的会话及 RustDesk 现有的近期会话重连授权不因此强制终止。

### 3.2 控制模式

主界面提供三种输入方式，都解析出同一种配对码：

| 方式 | 说明 |
|---|---|
| 扫码 | 调用摄像头实时识别（桌面端要求有摄像头；移动端是主要方式） |
| 载入图片 | 选择或拖入二维码截图（PNG/JPG），也支持直接从剪贴板粘贴图片 |
| 粘贴文本 | 粘贴 `SEALDESK:` 开头的配对码文本 |

解析成功后直接发起连接，并自动用配对码里的密码登录，**用户不需要再输入任何东西**。
连接后窗口标题显示被控端名称（`N` 字段），工具栏显示链路类型：P2P 直连 或 DERP 中继。

最近的连接只在本机保存 tc 地址和名称（密码按 RustDesk 原有的"记住密码"开关决定是否保存），方便下次一键重连。

## 4. 配对码协议（二维码载荷）

参照 Wi-Fi 分享二维码（`WIFI:T:WPA;S:ssid;P:pass;;`），用纯文本、字段式的格式，方便人读、方便调试，也能直接复制粘贴。

### 4.1 格式

```
SEALDESK:V:1;A:<tc地址>;P:<临时密码>;N:<设备名>;E:<过期时间>;;
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `V` | 是 | 协议版本，当前为 `1`。控制端遇到不认识的大版本号时提示升级 |
| `A` | 是 | tc 地址 |
| `P` | 否 | RustDesk 临时密码。没有这个字段时，连接后弹出密码输入框（用于只用固定密码、不愿把密码放进码里的场景） |
| `N` | 否 | 被控端显示名（默认取主机名），只用于界面显示 |
| `E` | 否 | 控制端使用截止时间，Unix 秒。官方控制端到期后拒绝导入并提示"请让对方刷新二维码"；它不是服务端凭证撤销机制 |

规则：
- 前缀 `SEALDESK:` 不区分大小写；字段名区分大小写；字段顺序任意；遇到不认识的字段忽略，以便向前兼容。
- 字段值里的 `\` `;` `,` `:` `"` 用反斜杠转义，规则和 Wi-Fi 二维码一致。tc 地址是 base64url，不需要转义。
- 末尾的 `;;` 表示结束。

示例：

```
SEALDESK:V:1;A:tcpGFwWCD9vGW9EFoJ4QfhrEKic1sZ9C...;P:k3m9xq;N:my-desktop;;
```

### 4.2 二维码参数

`E` 只是官方控制端的导入策略。被控端不验证这个字段，其他客户端或手动使用相同 tc 地址和密码仍可连接，不能把"二维码到期"等同于"访问权限被撤销"。要撤销旧临时密码的新登录能力，必须刷新临时密码；要撤销 tc 地址本身，必须重置地址。点击确认模式不在码里附带临时密码。

- **编码**：Byte 模式，纠错等级 M（截图压缩、拍屏都能识别）。载荷约 180–200 字节。M 级下版本 10（57 模块）可以容纳 213 字节，所以一般是版本 10；带上较长设备名时可能到版本 11，屏幕上显示 ≥ 240 px 就能稳定识别。
- **显示**：周围留 4 模块宽的静区，黑码白底；不跟随深色主题反色。
- **命令行模式**：用 Unicode 半块字符在终端里打印二维码（原型已实现），给无界面的服务器用。

### 4.3 安全说明

配对码 = tc 地址（能连上这台机器）+ 临时密码（能登录），**应视为远程访问凭证**。它可被重复使用，不具有服务端的一次性消费保证。

- 界面上默认显示二维码；可以加一个"遮挡"开关（点击才显示），并提示"仅向信任的人展示"。
- 默认带上 `E` 字段，供官方控制端限制 10 分钟内导入。密码在会话后刷新按 RustDesk 原有规则执行，不能据此承诺已建立会话或近期会话重连授权失效。
- tc 地址长期不变，泄露后需要能在被控端"重置地址"（重新生成密钥，之前所有二维码失效）。
- 可选白名单：被控端只允许指定控制端的公钥（`nodekey:...`）连入（原型里是 `tailcat-allow` 选项）。

## 5. 安全模型

| 层 | 机制 |
|---|---|
| 传输 | WireGuard，端到端加密。PSK 防止 DERP 运营方或旁观者冒充被控端，并提供抗量子保护 |
| 寻址与认证被控端 | tc 地址里包含被控端公钥，连上的一定是持码那台机器 |
| 认证控制端 | RustDesk 密码登录（临时密码或固定密码），可再叠加 tailcat 白名单 |
| 暴露面 | 被控端只在 127.0.0.1 上监听，不在局域网或公网开端口；没有 ID 服务器，也就不存在可被枚举的设备 ID |

RustDesk 原有的 `secure_connection`（用 rendezvous 服务器签名做密钥交换）随服务器一起移除。tailcat 会话视为已加密，不再弹出"不安全连接"确认。

## 6. 原型现状（分支 `tailcat`）

已实现：
- `libs/tailcat-ffi/`：Go 的 c-archive 静态库，导出 `TcServe` / `TcForward` / `TcPath` / `TcClientPubkey` / `TcQR`。`build.rs` 会自动编译并链接它。
- `src/tailcat.rs`：Rust 封装；被控端的密钥和 DERP 区域会持久化，tc 地址跨重启不变。
- 被控端：`rendezvous_mediator.rs` 精简成只有 tailcat 接入（1800 行 → 125 行），不再注册 ID 服务器，也不再在 21118 端口对外监听。
- 控制端：`client.rs` 里的 rendezvous、UDP/TCP 打洞、WebRTC、中继代码已移除；tc 地址走隧道，局域网 IP 直连保留。
- 删掉启动时的 NAT 探测和 ID 服务器探测；在线状态查询改成本地返回。
- 程序名改为 `SealDesk`，配置、日志和 IPC 与原版 RustDesk 隔离。
- 命令行：`--tc-addr`（打印地址和终端二维码）、`--tc-pubkey`、`--tc-allow`；便携模式下允许 `--password`。
- 总改动：约新增 150 行，删除 3900 行。

已验证（同一台 Linux 机器上）：
- FFI 层：隧道收发正常，P2P 直连建立，未在白名单的客户端被拒绝，tc 地址跨重启不变。
- 被控端：官方 RustDesk 客户端经 tailcat 隧道连入，密码登录成功，开始 AV1 推流。
- 控制端：SealDesk 用 tc 地址发起连接，隧道建立并报告 `direct`，被控端收到会话。

**待验证 / 已知问题**：
- 控制端会话曾因"不安全连接"确认框而关闭。已修复，并在真实 tailcat 隧道中用原生控制端连接与密码处理器验证登录成功、加密判定为 `secure=true`；完整 GUI 画面会话仍待验证。
- 还没有做跨网络（不同 NAT）的打洞测试，本机自连不能说明问题。
- debug 版搭配新版 `libsciter-gtk.so` 会因为枚举值不匹配崩溃；release 版正常。
- release 版 Sciter 界面需要从仓库根目录启动（按当前目录找 `src/ui/*.html`），或者用 `inline` feature 编译。

### 2026-10-15 安全二次复核：换钥猜密码与缓存回收

- `src/tailcat/auth_limit.rs` 增加所有 tailcat 会话共享的密码验证令牌桶：最多积累 20 次突发额度，每 5 秒补充 1 次，使用单调时钟。临时密码、固定密码及走现有密码失败检查的终端 OS 凭证入口均受限；更换控制端密钥或新建连接不重置此预算。
- 先执行原有单来源失败检查，通过后才消耗共享预算。被单来源锁定的重复请求不会继续耗尽其他人的预算。共享预算耗尽时，新密码登录收到“请稍后再试”，补充额度后自动恢复；持续攻击仍可能争抢新登录额度，不能承诺攻击期间的新登录可用性。已授权会话、近期会话授权和点击确认沿用原有策略。
- `libs/tailcat-ffi/transport.go` 移除身份分配表和递增编号，以 HMAC-SHA256 和每进程随机盐将认证公钥映射到 `fd` 开头的 120 位哈希标识。映射不随控制端数量分配表项，也没有约 400 万身份的耗尽条件。同一密钥在本进程内保持稳定，碰撞概率不为零；限流标识不替代 tailcat 的公钥认证。
- 本机元数据改为 32 字节通道凭证加 16 字节虚拟地址；只有认证后的入口设置 `via_tailcat`。虚拟地址不参与物理 IPv6 前缀聚合。tailcat 失败记录与普通网络来源隔离，每类最多 4096 条，10 分钟后的旧记录按访问或容量压力淘汰，防止换钥把内存增长转移到密码失败表。
- `libs/tailcat-ffi/client_cache.go` 按活动会话和路径探测计数引用，最后一个引用释放时移除缓存并调用 `Client.Close()`，同时限制最多 64 个活动目标。拨号失败、转发取消、未领取超时及会话结束均释放引用；同时连接同一目标仍可复用客户端。保留原始连接对象传给隧道代理，半关闭和响应完整性有回归测试。
- 验证：22 项 Rust 配对码、通道和认证限速测试、3 项未登录连接限额测试及 1 项白名单测试通过；Go 12 项测试通过竞态检测，覆盖身份与目标各 1 万次轮换、并发引用、回收和半关闭。Linux debug 原生可执行文件构建通过。
- 隔离真实协议服务中，固定密钥输错触发原有每来源限流后独立控制端仍可登录；24 个不同配置目录生成的新控制端密钥连续猜密码触发共享预算，等待补充后新控制端无需重启服务即可登录。该测试纳入 `tests/sealdesk_live_security.py`，不等同于 GUI 首帧或跨 NAT 验收。

## 8. 验收标准

1. 两台在不同 NAT 下的机器，被控端从启动到显示二维码 < 5 秒；控制端扫码或载入图片到看到画面 < 10 秒，全程没有输入框。
2. 打洞成功率在常见家用和办公 NAT 组合下 ≥ 90%；失败时自动走 DERP，仍然能用。
3. 抓包确认：除了 DERP 会合和 STUN 之外，不连接任何 RustDesk 公共服务器（`rs-*.rustdesk.com` 等）。
4. 篡改配对码中的 tc 地址或 PSK 后无法连接；过期的码被控制端拒绝；不在白名单的控制端被拒绝。
5. 被控端在局域网和公网上没有开放任何监听端口（`ss -ltn` 中只有 127.0.0.1）。

## 9. 风险

| 风险 | 应对 |
|---|---|
| tailcat 还没有稳定的 API 或协议承诺 | 锁定 commit；FFI 层保持很薄，方便升级 |

| 对称 NAT 两端都打洞失败 | 走 DERP 兜底，界面上明确提示 |
| 二维码泄露 | 官方控制端检查导入截止时间；服务端撤销须刷新密码或重置地址，另提供遮挡开关和白名单 |
